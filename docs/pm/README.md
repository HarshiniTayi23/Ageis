# Product track

Aegis is built twice: once as software, once as a product. Every milestone ships a PM document *before* the code it describes, so the reasoning is visible next to the implementation.

| # | Document | Status | PM skill it practises | Written before |
|---|---|---|---|---|
| 01 | [Problem statement](01-problem-statement.md) | Draft v0.1 | Framing a problem with evidence | Any code |
| 02 | [Personas](02-personas.md) | Draft v0.2 | Naming the user precisely | Any code |
| 03 | [User research](03-user-research.md) | Template | Testing assumptions with real people | PRD |
| 04 | [PRD: M1](04-prd.md) | Draft v0.1 | Writing requirements engineers can build from | Milestone 1 |
| 04b | [PRD: M2 agent undo](04b-prd-m2-agent-undo.md) | Draft v0.1 | Same, for a newer, less-defined problem | Milestone 2 |
| 05 | [Roadmap](05-roadmap.md) | Draft v0.2 | Prioritising and saying no | Milestone 1 |
| 06 | [Competitive analysis](06-competitive-analysis.md) | Template | Positioning | Milestone 2 |
| 07 | [AI evaluation plan](07-ai-eval-plan.md) | Template | Measuring an AI feature before trusting it | Milestone 3 |
| 08 | Launch package (README, demo video, one-pager) | Not started | Telling the story | End |
| 09 | Retrospective | Not started | Learning from what went wrong | End |

Engineering decisions live separately as [Architecture Decision Records](../adr/).
